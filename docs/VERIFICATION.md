# Verification and provenance

The state-count hierarchy and finite-pulse witness are analytic results.
Computational checks reproduce the evidence attached to their own claims;
a passing workflow is not a substitute for the proofs.
The [results index](CLAIM_LEDGER.md) maps R1–R98 to their evidence, and the
[proof review](FINAL_SANITY_AUDIT.md) records the completed internal
proof review and full local reproduction.

## Run the checks

From the repository root:

```bash
python -m pip install -r requirements.txt
make check
```

The [Makefile](../Makefile) is the authoritative command inventory:
repository hygiene and provenance checks, 77 mathematical verifiers, and
four deterministic replays of saved models. Optional optimizers are not
run. Fresh reports go to `.check-output/`; the saved evidence in
[`reports/`](../reports/) is preserved. Dependency versions are pinned in
[`requirements.txt`](../requirements.txt).

For a documentation-only check:

```bash
python scripts/check_repository.py
```

That checker validates local link destinations, fence balance, Python
syntax, saved source/proof/input-report hashes and the original license.
It does not validate heading fragments, visual equation layout or
mathematical correctness. Rendering changes also require inspection in
GitHub's rendered view, especially numbered displays, matrices, sets and
inequalities.
Use GitHub inline-math wrappers and fenced `math` displays. Keep equation
numbers outside the math block as text labels, and use mathematical
commands for inequality signs and table-cell absolute-value delimiters.
These presentation conventions preserve formulas while avoiding the
collapsed numbered displays and broken inline notation seen in GitHub.

## What each kind of evidence establishes

| Evidence | Interpretation |
| --- | --- |
| Analytic argument | The theorem under its explicit assumptions and quantifiers; review the linked proof |
| Exact or interval certificate | The certified statement in its original task and parameter range |
| Floating-point or high-precision comparison | A consistency check, unless a separate exact or interval argument is supplied |
| Saved-model replay | Reproduction of a previously stored model; no new search or optimality claim |
| Internal proof review | An independent internal check; no external peer-review endorsement |
| Local PASS or hosted CI | Successful execution for that local tree or exact hosted commit; no priority, impact or acceptance claim |

Detector, calibration and sample-count guarantees apply to their specified
observation contracts and do not transfer automatically to the R98 pulse menu.

## Preserve and update evidence deliberately

Saved reports must be generated by their owning verifier after reviewing
the affected claim and dependencies; never hand-edit a numerical result
or a recorded hash. Proof snapshots and input-report hashes bind reports
to exact source bytes. Review that dependency chain before changing a
bound proof, even for formatting. The preserved checkpoint verifier is an
immutable regression baseline.

The [proof review](FINAL_SANITY_AUDIT.md) records the analytic and
computational checks. Local and hosted Python-version metadata may differ.
Hosted results are available in
[GitHub Actions](https://github.com/GoGoKo699/Intervention-Reuse-Limits/actions);
match the run's commit to the version being inspected.
